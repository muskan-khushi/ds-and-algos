# 🔥 SLIDING WINDOW & TWO POINTERS

## **ABSOLUTE MAXIMUM DETAIL — MAANG / SYSTEMATIC THINKING LEVEL**

---

## 🧠 ZERO-LEVEL FOUNDATION (MOST IMPORTANT)

### What sliding window REALLY is

Sliding Window is **not a trick**, it is an **optimization of brute force**.

Brute force:

* For every `L`
* Try every `R`
* Recompute everything

Sliding window:

* **Reuse previous computation**
* Maintain a **running state**
* Move pointers **only forward**

> If you ever feel “this looks magical”, stop and ask:
> **What state am I carrying instead of recomputing?**

---

## 🧩 Two Absolute Preconditions for Sliding Window

### 1️⃣ Window validity must be **monotonic**

Meaning:

* Expanding window makes condition **worse**
* Shrinking window makes condition **better**

Example:

* `sum ≤ k` → expanding increases sum ❌, shrinking decreases sum ✅
* `distinct ≤ k` → expanding may increase count ❌, shrinking decreases count ✅

🚨 If this is NOT true → sliding window FAILS.

---

### 2️⃣ Pointers must never move backward

* `L` only increases
* `R` only increases

This guarantees **linear time**.

---

# 🔹 PATTERN 1: CONSTANT WINDOW (FIXED SIZE)

---

## 🧩 Problem Nature

> “Exactly k consecutive elements”

Window size = **constant**
Window position = **variable**

---

## 🧠 Invariant (INTERVIEW GOLD WORD)

At all times:

```
window size = k
sum = sum of elements inside window
```

---

## 🪜 Step-by-Step Logic

1. Build the **first valid window**
2. Slide window by:

   * Removing leftmost element
   * Adding next element

You are not “changing window”, you are **translating it**.

---

## ❌ Common Wrong Thinking

> “For every window, calculate sum”

That destroys the entire point.

---

## 🧪 Ultra-Clean Template

```cpp
int windowSum = 0;

// build first window
for (int i = 0; i < k; i++) {
    windowSum += arr[i];
}

int best = windowSum;

for (int i = k; i < n; i++) {
    windowSum += arr[i];     // add new
    windowSum -= arr[i - k]; // remove old
    best = max(best, windowSum);
}
```

---

## ⏱ Complexity Proof

* Each element added once
* Each element removed once
  → **O(N)**

---

## 🧠 Interview Narration

> “Since the window size is fixed, I maintain the sum dynamically and slide the window in constant time per move.”

---

# 🔹 PATTERN 2: LONGEST SUBARRAY / SUBSTRING

🔥 **THIS IS THE HEART OF SLIDING WINDOW**

---

## 🧩 Problem Nature

> “Longest window that satisfies condition”

Window size = **dynamic**
Validity = **fragile**

---

## 🧠 Core Invariant

At any time:

```
Window [L..R] is VALID
```

If it becomes invalid → **fix it immediately**

---

## 🔁 Better Approach (Classic Sliding Window)

### Why `while` loop?

Because **one shrink is not guaranteed to fix validity**.

Example:

```
sum = 100, k = 50
arr[l] = 10
```

Removing one element is not enough → keep shrinking.

---

## 🧪 Template (MEMORIZE THIS STRUCTURE)

```cpp
int l = 0, state = 0, ans = 0;

for (int r = 0; r < n; r++) {
    state += contribution(arr[r]); // expand

    while (state is invalid) {
        state -= contribution(arr[l]); // shrink
        l++;
    }

    ans = max(ans, r - l + 1);
}
```

---

## ⏱ Why O(2N) is Still O(N)

This question WILL come.

Answer:

* `r` goes 0 → n-1
* `l` goes 0 → n-1
* No pointer ever resets

> Total pointer moves ≤ 2N

---

## 🚨 FAILURE CASE (EXTREMELY IMPORTANT)

### ❌ Negative numbers

Example:

```
arr = [3, -2, 5]
k = 4
```

Shrinking doesn’t guarantee improvement.

👉 Use **Prefix Sum + HashMap** instead.

---

## ⚡ Optimal Approach (Non-Shrinking Window)

---

## 🧩 Why This Works

You only want **maximum length**, not window itself.

If a window of length `X` is invalid:

* Any smaller window ending at same `R` is **useless**
* Only larger windows matter

---

## 🧠 Key Mental Shift

You **never shrink aggressively**
You only **shift window once**

---

## 🧪 Template

```cpp
int l = 0, sum = 0, ans = 0;

for (int r = 0; r < n; r++) {
    sum += arr[r];

    if (sum > k) {
        sum -= arr[l];
        l++;
    }

    if (sum <= k) {
        ans = max(ans, r - l + 1);
    }
}
```

---

## 🚨 STRICT CONDITIONS FOR THIS TEMPLATE

✔ Only length required
✔ All numbers ≥ 0
✔ Condition monotonic

If any fail → **DON’T USE**

---

# 🔹 PATTERN 3: COUNT SUBARRAYS

---

## 🧩 Problem Nature

> “Number of subarrays satisfying condition”

Counting is harder than maximizing.

---

## ❌ Why Direct Sliding Window Fails

Equality (`=`) is **unstable**:

* Expanding breaks it
* Shrinking breaks it

No direction guarantees progress.

---

## ✅ THE MAGIC TRANSFORMATION

```
Exactly K = AtMost(K) - AtMost(K - 1)
```

---

## 🧠 Why AtMost Works

“At most” conditions are **monotonic**.

If sum ≤ k:

* Shrinking keeps it ≤ k
* Expanding may break it

Perfect for sliding window.

---

## 🧪 AtMost Template (SUPER IMPORTANT)

```cpp
int l = 0, sum = 0, count = 0;

for (int r = 0; r < n; r++) {
    sum += arr[r];

    while (sum > k) {
        sum -= arr[l];
        l++;
    }

    count += (r - l + 1);
}
```

---

## 🧠 WHY `count += (r - l + 1)`?

All subarrays:

```
[l..r], [l+1..r], [l+2..r] ... [r..r]
```

All are valid.

---

## 🎯 Final Answer

```cpp
exactlyK = atMost(K) - atMost(K - 1);
```

---

# 🔹 PATTERN 4: SHORTEST / MINIMUM WINDOW

---

## 🧩 Problem Nature

> “Minimum window that satisfies condition”

Opposite of longest.

---

## 🧠 Core Invariant

When valid:

```
Try to make it smaller
```

---

## 🪜 Step Logic

1. Expand `R` → reach validity
2. Shrink `L` **as much as possible**
3. Update answer **during shrinking**

---

## 🧪 Template

```cpp
int l = 0, sum = 0, ans = INT_MAX;

for (int r = 0; r < n; r++) {
    sum += arr[r];

    while (sum >= k) {
        ans = min(ans, r - l + 1);
        sum -= arr[l];
        l++;
    }
}
```

---

## ⚠️ Interview Trap

If you update answer **after loop**, you miss minimal window.

---

# 🧠 MASTER DECISION TABLE

| Question Type   | Window Behavior     | Loop  |
| --------------- | ------------------- | ----- |
| Fixed size      | Never change size   | for   |
| Longest         | Shrink till valid   | while |
| Optimal longest | Shift once          | if    |
| Count exactly   | AtMost trick        | while |
| Shortest        | Shrink aggressively | while |

---

# 🏆 FINAL INTERVIEW MANTRA

> “Sliding window works because I maintain a valid window using monotonic pointer movement and incremental state updates.”
